## 구현·검토 상태

수집·검증 Python은 `gpt-6-luna`가 작성하고 `gpt-6-astra`가 OCR 파일 선정·규칙 확인 후 검토했다. 차단 결함을 수정하고 재검토한 버전만 실 API에 실행했다. 최종 코드의 오프라인 회귀 검사 25개가 통과했다. 이는 예측성능 검증이 아니다.

현재 승인된 `agri_data/collector.py` SHA-256은 `e3ca950508ad1545cfe73f6441b33241433556eeb1815f69c0742f518793e383`, 테스트는 `fc219a83f751d6b4492c5a98da9c792ed41c4a5564fd734fb22397b1777092ac`다. 코드 커밋은 `a88e987`이다. 최초 생산자료 실행은 `b4b5a66c0028842fc67661d87f0f0672d9e14276281af81fd28bbc7ecea69721`, 완료된 기상 실행은 `20757f31b224dea44ae73fa0f36d1125cd59f0b35e37d1c57309752e04c6eded` 버전이었다. 이후 차이는 ASOS 응답 처리와 수입 요청 묶음에 한정된다.

실행에서 ASOS `numOfRows=1000` 요청은 오류 99를 반환했고, 999로 낮춘 뒤 과거 무자료의 `03 / NO_DATA` 응답을 확인했다. Luna가 정확한 응답 변형만 추가하고 Astra가 재승인했다. 실패 원응답은 DB에 남아 있으며 성공으로 덮어쓰지 않았다.

추가한 읽기 전용 가격 범위 점검기 `agri_data/coverage.py`도 Luna가 작성하고 Astra가 검토했다. 재개 시각 때문에 오래된 응답을 최신으로 선택하던 문제와, 같은 작업의 새 수집이 미완료일 때 이전 완료 버전을 놓치던 문제를 수정했다. 대규모 조회에서는 요청 메타데이터를 사전 집계하고 동일 조회 키로 연결하며 페이지 행수는 기본키 인덱스로 확인한다. 이 성능 수정도 Astra 재검토 후 실행했다. 승인 SHA-256은 모듈 `8ec85b619da28c6f96da008fbd9235620f4c03c479d647f9eed281584d51b658`, 테스트 `872cefcfed1b8b8d93e0299c73661e51429c794f5281d56663eb36ae500a57d6`다. 전체 오프라인 검사 33개, 추가 페이지 무결성 검사와 변경 전후 조인 결과 일치 검사도 통과했다. 최종 실 DB 범위 점검은 약 15초에 완료됐다. 기존 수집 코드는 변경하지 않았다.

2026-09-28 요청에 따라 macOS 사용자 crontab에서 매일 **09:00 KST**에 장기 가격 수집을 실행하도록 구성한다. 시스템 시간대가 Asia/Seoul인 환경을 기준으로 하며, 다른 시간대로 변경하면 예약 실행 시각도 다시 확인해야 한다. 기존 다른 프로젝트의 crontab 항목은 보존한다. 일반 cron은 놓친 실행을 자동 보충하지 않으므로 수집 시각의 시스템 가동과 인터넷 연결이 필요하다.

**잠자기 해제 예약(2026-09-29):** 추가 요청에 따라 관리자 인증을 거쳐 `pmset repeat wake MTWRFSU 08:59:00`을 설정했다. 01:04 KST에 `pmset -g sched`의 `wake at 8:59AM every day`를 확인했다. 매일 수집 1분 전에 잠자기에서 깨어나도록 하는 설정이며, 전원이 꺼진 Mac의 자동 부팅을 예약한 것은 아니다. 기존 반복 전원 예약은 없었고, 기존 일회성 전원 예약 2개는 보존했다. 설정 전 목록은 `runs/power-schedule-before-wake.txt`에 남겼다. 이후 09:00 수집 실행은 확인했으나, 직전에 실제 잠자기 상태였는지 및 예약으로 깨어났는지는 별도로 검증하지 않았다.

**2026-09-29 실행 및 정책 변경:** 첫 예약 실행은 09:00:01~09:31:48 KST에 HTTP 2,803회를 사용해 2016년 1분기 잔여분(job 17)과 4~12월(job 18)을 완료했다. 두 작업의 미완료·대기·실패 조회는 0개이며 정상 0건 응답을 포함한 조회 완료다. 2016년의 모든 날짜에 유효 거래가 있다는 뜻은 아니다. 이 시점에 로컬 일일 예산은 6,197회 남았다.

일일 실행예산은 이 DB에 기록된 KST 당일 HTTP 시도 누적 **9,000회**이며 코드·페이지·재시도를 포함한다. 이는 계정의 실제 남은 호출량을 보장하는 값이 아니다. 한도·인증·반복 오류가 발생하면 당일 추가 진행을 중단한다. 중복 실행 잠금과 가용 디스크 **5GiB** 하한을 두며, 원응답·실패·정상 0건·수집시각·출처를 기존 DB에 보존한다. 수집기 자체는 학습을 수행하지 않는다. 2026-09-30 추가 승인에 따라 cron 진입점은 수집 후 학습·평가·통계 검토·대시보드 갱신으로 이어진다. 기존 동결 평가는 보존하고 대시보드 파일은 백업 후 교체한다.

현재 진행 상태는 `runs/daily-collection-status.json` 하나에 교체 저장한다. 호출 전에 작은 묶음의 예산을 예약하고, 강제 종료로 사용량 정산이 끝나지 않은 실행은 같은 날 다시 호출하지 않는다. `runs/daily-collection.log`는 파일당 2MiB, 백업 1개로 순환 보관한다. 조회 이력과 실제 HTTP 시도는 기존 SQLite 테이블에 남으며, 이 운영 상태 파일이 원자료 출처 기록을 대체하지 않는다.

```bash

crontab -l
```

가격 명령은 `prices --source origin` 또는 `--source sale`에 기간과 반복 가능한 `--market`을 지정한다. `--crop`을 생략하면 배추·무·양파·마늘·건고추의 중분류 원자료를 모두 수집한다. 마늘 전체를 깐마늘 최종 타깃이라고 해석하지 않는다. 깐마늘 소분류만 조회하려면 `--crop garlic --garlic-subcodes`를 지정한다. 품목 코드의 역사적 유효성은 별도 검증한다.

같은 조건의 미완료 작업을 재실행하면 그 작업 안의 완료 조회를 재사용하고 나머지를 재개한다. 이미 작업 전체가 완료됐으면 새 작업으로 다시 수집하므로 여러 작업의 같은 관측값을 무조건 합산하지 않는다. `--max-requests`는 코드 조회·재시도를 포함한 이번 실행의 실제 HTTP 시도 한도다. 한도 소진은 미완료 상태와 종료코드 2로 남긴다. `--refresh`는 재개하는 작업에서도 완료 조회의 새 응답 버전을 만든다. 수입은 최대 12개월, 기상은 최대 365일 묶음으로 요청하고 페이지 완전성을 확인한다. 수입 정책 표식을 작업 설정에 남겨 이전 월별 작업과 혼합하지 않는다.

DB에는 `jobs`(실행 조건), `planned_queries`(전체 계획/현재 상태), `request_attempts`(실제 HTTP 시도), `source_requests`(원응답·해시·출처·수집시각·버전), `raw_records`, `normalized_records`를 보관한다. 일별 파일은 생성하지 않는다. 정규화 행은 원문 필드를 JSON으로 유지하며 날짜와 품질 표시를 추가한다. 최종 일별 가격 타깃이나 백테스트용 특성 테이블을 만들어 둔 것은 아니다.

연간·월간 자료의 `reference_date`는 편의를 위한 해당 연도/월 첫날이다. 실제 일별 관측일이나 공개일이 아니다. 원문의 `PRD_DE`/`year`와 통계 주기를 함께 읽어야 한다. 모든 신규 응답은 `current_retrieved_vintage`이며, 확인하지 못한 `published_at`과 `version_published_at`은 null로 남긴다.

`validate`는 요청·페이지·행 수·관계 무결성·완료 상태를 검사하며 미완료 작업이 포함되면 실패를 반환한다. 품질 표시는 원자료 해석상의 주의사항으로 별도 출력한다. `quality_flags` 합계는 보관된 모든 응답 버전을 포함하므로 고유 관측 건수와 다를 수 있다. 사용할 버전은 `planned_queries.epoch_id`와 연결해 선택한다. 원천 API가 원자적 스냅샷을 제공하지 않으므로 페이지 조회 중 총건수가 그대로인 내용 변경까지 완전히 검출할 수는 없다.

월별 실제 확보 범위는 다음 명령으로 확인한다. 출력은 월×시장×품목군×원천/정산×소분류 조회 범위별 JSON이며 DB를 수정하지 않는다.

```bash
python3 -m agri_data.coverage --db data/agri.sqlite > runs/coverage.json
```

같은 날짜·시장·품목 조회의 중복 작업은 응답 수집시각을 기준으로 최신 완료 버전을 선택한다. 최신 완료 결과가 정상 0건이면 옛 자료가 있는 응답을 대신 사용하지 않는다. 최신 시도가 미완료이면 페이지·건수·원문/정규화 연결을 확인한 이전 완료본을 사용할 수 있으며 그 사실을 `fallback`으로 표시한다. 불완전한 페이지를 확보 거래로 포함하지 않는다. 중분류 전체와 깐마늘 소분류 조회는 겹치므로 별도 범위로 출력하며 합산하지 않는다.

월 전체 날짜 수, 실제 계획한 날짜 수, 완료 조회일, 자료가 있는 날, 정상 0건일, 대기·실패·미완료일을 구분한다. 하루 표본 조회 완료를 한 달 전체 확보로 표시하지 않는다. 이 도구의 건수는 선택된 응답 행 기준이며 개별 거래 ID의 업무상 유일성이나 최종 타깃 적합성까지 입증한 수치가 아니다. `mdfcn_dt` 등 원문 필드 분포와 공개시각 미확인 상태도 함께 남긴다.

별도 Google 복제 보관소를 같은 고정 객체키로 한 번 조회했다. 인덱스 HTTP 200·34,294바이트·SHA-256 `809f14048504dada2849cbfa55dd39c89ad0d37d5bf36ab9a4c89e9a9b2070ad`는 AWS 원본 인덱스와 같았다. 객체 HEAD는 126,472,991바이트와 `Last-Modified` **2025-08-31 20:34:19 UTC**를 반환했고, 고정 665,726바이트 범위 GET은 HTTP 206·정확한 `Content-Range` 및 GRIB2 경계/자체 길이로 완료됐다. 원문 필드 `data/raw/ecmwf_operational_probe/ecmwf_ifs_20250831T1200_step24_20261007T085738951102Z_809f14048504_2t.grib2`의 SHA-256은 `0ea3631f06bc8d7f48e6814f5b51ed57402998a406eb1c2b8b9774f9a16c6579`다. 동명 `.index`와 `.meta.json`도 Git 제외 위치에 보존했다. 이는 원본 바이트 확보와 전달 정합성 검증이다. 객체 수정시각만으로 최초 대외 공개시각, 현재 Open-Meteo 9km 실행본과의 수치 동일성, 전체 기간 coverage를 입증하지 않는다. 모델 성능에는 반영하지 않았다.

그 단일 필드를 ecCodes v2.48.0으로 해독한 [한 점 비교 보고서](../outputs/experiments/ecmwf-field-compare-one-point/report.json)는 원본 격자 `(34.5,126.5)`의 2025-09-01 12UTC 기온 26.833°C, Open-Meteo 반환 격자 `(34.622143,126.59091)`의 26.0°C, 차이 +0.833°C를 기록했다. 원본 격자는 요청 좌표에서 12.02km 떨어진 최근접 점이다. 서로 다른 격자 해상도·보간 방법 때문에 숫자 차이만으로 동일·불일치를 판정하지 않는다. **단일 필드·단일 시각만 해독 완료**이며, 기간 전체·가격 성능에는 미반영이다.

고정한 세 날짜 `2025-09-14`·`2026-03-14`·`2026-09-22`의 12UTC 운영 실행본 24h 파일에서 Google 인덱스와 객체 HEAD를 각 한 번씩 조회했다. 모두 HTTP 200, 해당 2t 기록 한 건, 인덱스 범위가 객체 크기 이내, 전송 재시도 0건이었다. 원본 인덱스 SHA-256은 날짜 순서로 `fb3ca9be0843c25f1c13c847539fe963dbd475b69f9d11d5bf90f190b88202c3`, `bd5aa17022687c105466f18f248a84e62d1619d1d535312c4017434cbf84cde4`, `52c5c7751907ca9fb9e8c0e4eac0b222e0c824a14e6ed7d050efb06899d12fde`다. Git 제외 `data/raw/ecmwf_archive_coverage/`에 원문과 날짜별 상태 메타데이터를 보존했다. 객체 `Last-Modified`는 각각 2025-09-14 20:34:18, 2026-03-14 19:34:20, 2026-09-22 19:34:22 UTC로 다음날 10:00 KST 원점 전이다. 보관 경로의 세 표본만 확인됐고 그 사이 날짜·다른 예보 거리·강수/공개시각·모델 성능은 확인되지 않았다.

[GCS 객체 목록 API](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/list)로 `2024`·`2025`·`2026` 날짜 경로를 페이지 끝까지 조회했다. 각 연도의 HTTP 200 페이지는 8·8·6쪽이고 보존한 `YYYYMMDD/` 경로는 366·365·280개였다. 원문 응답·해시·페이지 토큰·요약은 Git 제외 `data/raw/ecmwf_archive_listing/`에 보존했다(요약 SHA-256 `0fe5fbb2f11bcc18ebbb3f77c576dfe62128fece5c066469624f4a5577ba63c7`). 학습 목표일 2024-01-01~2025-09-01의 **날짜 경로**는 610/610일, 평가 원점 전날 2025-09-14~2026-09-22는 374/374일이었다. 날짜 경로만으로 실제 12UTC 실행본·거리별 2t/tp 필드·원점 전 공개가 입증되지는 않는다.

같은 해독기로 다시 만든 [최종 특징량](../outputs/experiments/ecmwf-point-features-20261007/features_fe353b1d99a785fee5f23fa3f9acfad71445c231aaa01f649e49258b44717fe0.json)의 SHA-256은 `fe353b1d99a785fee5f23fa3f9acfad71445c231aaa01f649e49258b44717fe0`, [manifest](../outputs/experiments/ecmwf-point-features-20261007/manifest_737b36aa5f0f938d45eaf18e5ef9e97e928857960ed46f3c2cb812edb86a6686.json)는 SHA-256 `737b36aa5f0f938d45eaf18e5ef9e97e928857960ed46f3c2cb812edb86a6686`다. 922개 원본 체크포인트 해시가 연결됐고 918일은 18개 특징량 모두 유효, 위 4일은 결측 사유 `last_modified_not_before_origin`으로 남겼다. 가격 모형 비교는 [계획과 결과](PLAN.md)의 고정 절차를 참조한다.

이 절의 원본 검증은 수집·저장 정합성과 원자료의 사용 제한에 관한 것이다. ECMWF 특징량을 사용한 후향 가격 비교와 DM 검정은 [계획과 결과](PLAN.md)에 따로 기록했다. 객체 수정시각만으로 당시 최초 공개시각을 증명하지 않았고, 공식 전국 목표나 사용자 혜택도 검증되지 않았다.

## 수입 코드와 요청 범위의 근거

[관세청 HS 연계표](https://www.customs.go.kr/ftaportalkor/cm/cntnts/cntntsView.do?cntntsId=1059&mi=3397)는 HS 2022 적용일을 2022-01-01로 안내한다. 다만 해당 연계표의 목적은 FTA 원산지기준 확인이며, 관세청 통계 API의 구·신 코드 중첩 행을 어떻게 합산할지를 입증하지 않는다. 양파와 건고추의 중첩 월은 앞서 기록한 제한을 유지한다.

[원천 API 명세](https://www.data.go.kr/data/15141810/openapi.do)에서 정산일자와 도매시장 코드는 필수 조회 조건이다. 공개 명세상 여러 날짜 또는 모든 시장을 한 번에 가져오는 요청은 확인하지 못했다. 따라서 문서화되지 않은 범위 조건으로 호출 수가 줄어든다고 가정하지 않는다.

## 본수집 범위와 중단 기준

가격은 2014년부터 확인된 원천자료를 출발점으로 삼아 기간·시장 범위를 확장한다. 이전 연도 표본 0건을 해당 연도 전체 부재라고 판단하지 않는다. 시장 코드 목록과 5품목군을 기준으로 날짜별 조회 계획을 남기고, 실행예산으로 나누어 진행한다. 가락 또는 몇 시장만 수집한 결과를 전국 가격으로 표시하지 않는다.

[원천 API 안내](https://www.data.go.kr/data/15141810/openapi.do)는 개발계정 10,000회와 일일 한도 오류를 명시한다. 따라서 단일 배치를 전체 장기 전국자료 수집 완료로 보고할 수 없다. 호출 한도 확대는 같은 API 페이지의 운영계정/트래픽 안내를 확인할 사항이며, 에이전트가 대신 신청하지 않았다. 실제 한도 도달과 자체 실행예산 중단을 결과에서 구분한다.

현재 추가 활용신청이 필요한 새 데이터셋은 확인되지 않았다. 예선 마감 전 위 탐색 상한까지 수집하려면 기존 원천 API의 운영계정/트래픽 확대를 검토해야 한다. 예를 들어 하루 50,000회가 허용되더라도 첫 페이지 요청만 약 16일이므로, 시장별 실제 수록기간을 좁히는 조사와 저장 용량 최적화를 병행한다. 이는 신청 규모 산정 예시이며 승인·실제 할당량·제공기관 서버 처리율을 보장하는 숫자가 아니다.

## 일별 도·소매 조사 가격의 원본등록시각 파일럿

[aT 일별 도·소매 가격 API](https://www.data.go.kr/data/15156057/openapi.do)는 경매가 아닌 중도매인 판매가격·소매가격 조사치를 제공하며, `exmn_ymd`(조사일), `exmn_dd_cnvs_prc`(kg 환산 조사일 가격), `orgnl_reg_dt`(원본등록일시)를 필드로 명시한다. 공식 Swagger의 HTTPS 경로는 `apis.data.go.kr/B552845/perDay/price`; 날짜 양끝·부류·품목 코드, 페이지 번호·페이지 크기·반환 형식이 필수이고 한 페이지 최대 1,000건이다. 제공자의 [인증 없는 표본 조회 화면](https://api.agromarket.kr/samples/public/perDay)은 채소류 `200`, 배추 `211`, 무 `231`, 건고추 `241`, 양파 `245`, 피마늘 `244`, 깐마늘(국산) `258`, 깐마늘(수입) `259`를 선택지로 표시한다. 이는 코드·명칭 확인일 뿐 각 품목의 실제 기간 coverage나 현재 경매 타깃과의 동일성 증거가 아니다. 특히 깐마늘 국산/수입 구분을 현재 타깃에 임의로 합치지 않는다. 등록일시가 최초 *대외 공개* 시각과 동일하다는 설명은 찾지 못했으므로 그 필드만으로 원점 전 이용 가능성을 확정하지 않는다.

실제 확대 수집 전에 위 세 품목의 2025-09-01~07 및 2026-07-01~07 두 7일 구간만 읽는 파일럿을 고정한다. 페이지를 끝까지 받아 원문·요청조건·응답 헤더/상태·페이지 총수·원문 해시를 보존하고 빈 응답, 인증 거부, 한도 초과, 일시적 오류를 구분한다. 항목 코드/명칭, 시장·품종·등급·가격 단위, 원본등록일시의 누락·형식을 검사한다. 조사일보다 늦은 등록과 다음날 10:00 KST 원점보다 늦은 등록 비율을 **자료 사용 결정 전에** 확인한다. HTTPS 검증·호출 속도 상한·시간제한·한정 재시도·체크포인트를 적용하고 프로젝트의 기존 공공데이터포털 키를 비공개로 읽는다. 파일럿은 수집 가능성과 시점 식별성 검사일 뿐 새 예측 성능을 평가하거나 이 조사 가격을 두시장 정답으로 바꾸지 않는다. 브라우저 엑셀 다운로드를 사용하지 않아 사용자 저장창을 띄우지 않는다.

2026-10-07 실행: Luna 작성·Astra 전 파일 재검토 완료 후 위 6개 범위를 고정하여 호출했다. 제한된 실행 환경에서는 24회 전송 시도가 모두 `URLError`로 끝났고, 네트워크 허용 실행에서는 각 범위가 HTTP 403으로 한 번씩 거절되어 유효 페이지·자료 행은 **0건**이다. 보존한 응답의 공공데이터포털 오류 코드는 `30 / SERVICE_KEY_IS_NOT_REGISTERED_ERROR`이며, [공식 오류 설명](https://www.data.go.kr/data/15156057/openapi.do)은 인증키 정확성과 이 서비스의 활용신청 완료 여부를 확인하라고 안내한다. 기존 키로 다른 서비스를 조회할 수 있는지와 이 서비스의 권한은 별개다. 실패 응답 원문·해시·시각·요청 범위는 무시 대상 `data/raw/daily-survey/`에 보존했고, 요약 결과는 같은 무시 대상 아래의 `daily-survey-pilot-report-network-20261007.json`(SHA-256 `a46327b1c933cd9dc4db0a61e478f3d1da3ed374c8cb65107dbdba6050b75616`)에 남겼다. 인증 없이 쓸 수 있는 표본 화면도 2026-07-01~07 배추 조회에서 `API 호출이 정상적으로 실행되지 않았습니다`를 표시하여 행을 얻지 못했다. 이 한 번의 화면 오류를 기간 전체의 데이터 부재로 해석하지 않는다. 따라서 이 신호의 기간 coverage·등록시각 분포·예측 성능은 아직 평가할 수 없다. 해당 서비스의 활용신청은 포털 로그인이 필요하다.

### 1. 정부 공급 발표: 보도시점이 실제 사용 가능 시점의 하한

농식품부의 [2025-07-06 배추 생산·공급 대책 원본](https://mafra.go.kr/bbs/home/792/588784/download.do)은 **배포 09:00, 보도시점 12:00**을 함께 적고 있습니다. 사전 수매계약·작목전환, 정부 가용물량 및 향후 공급 방침을 담고 있습니다. 따라서 같은 날 10시 예측에 배포시각만 보고 넣어서는 안 됩니다. 발표에 쓰인 가용물량은 저장·약정 등의 합계이고 실제 당일 출하량이 아닙니다. 개별 구성요소와 총계를 중복 합산하지 않습니다.

[2025-06-09 발표 원본](https://www.mafra.go.kr/bbs/home/792/588248/download.do)에도 보도시점 11:00과 배추·무 비축계획이 나타납니다. 이와 같은 발표를 날짜별 원본으로 모아 `계획 / 확보 / 방출 예정 / 방출 실적`을 구분하고, 품목·적용기간·물량·단위·대상 채널·발표시점·근거 문장을 보존하는 것이 현실적인 공개 경로입니다. 가격상승에 대응한 정책이라는 내생성이 있으므로 가격 하락을 유발하는 독립 원인으로 단정하지 않습니다. 특정 목표순에 물량을 배정할 일정이 없으면 목표순 물량을 임의 생성하지 않습니다.

**수집 착수 방식:** 농식품부 공식 보도자료 목록에서 배추/무 관련 발표를 일정한 기간 전체에 걸쳐 수집하고 PDF 원본·게시물·보도시점을 함께 보존합니다. 우선 개발연도 2022~2023을 같은 규칙으로 감사해 빈도와 원본 버전 지원을 확인합니다. 최근 사례 몇 건만으로 장기 학습자료를 확보했다고 표시하지 않습니다. 보도시점이 있어도 지금 내려받은 PDF가 당시 판본과 동일하다는 점은 별도 확인해야 합니다. 원점 전 공개를 입증할 수 없는 판본은 엄격한 후향 입력에서 제외하고 전향 보존 대상으로 둡니다.

### 3. 농넷 산지작황 Live: 실제 접근은 되지만 물량 데이터가 아님

2026-10-16 실제 브라우저에서 [산지작황 Live](https://www.nongnet.or.kr/front/M000000332/cropsFrc/farmList.do)를 로그인 없이 확인했습니다. 기본 검색기간 2025-01-01~2026-10-16의 화면 표시 건수는 **배추 1,370건·무 402건**입니다. 이것은 화면의 검색 결과 건수이며 고유 농가·고유 포전·출하면적·다운로드 검증 행 수가 아닙니다. 더 오래된 기간 지원도 이번에 확인하지 않았습니다.

배추 검색에서 ‘강원특별자치도 - 방제’ 기록을 열었을 때 상세 제목은 ‘강원특별자치도 | 고추 | 방제’, 작성일은 2026-10-13이었고, 본문에 고추 작업과 배추밭 방제가 함께 기재됐습니다. 상세는 [팜모닝 농작업 기록](https://farmmorning.com/posts/ZmFybWluZy1sb2ctcG9zdDo1Mjc5Nzk%3D)으로 연결됩니다. **농넷 화면에서 제공한다고 해서 aT의 대표 표본 작황조사나 공식 출하계획은 아닙니다.** 방제 기록을 병해 확정 발생량으로, 게시물 증가를 재배면적 증가로 바꾸지 않습니다.

활용 후보는 원문에서 명확한 배추·무의 파종·정식·수확 날짜/상태, 지역, 작형 전환 정보입니다. 최초 공개시각·작업일·작성일·수정일, 고유 포전 구분, 중복과 재게시, 표본 편향을 확인해야 합니다. 해당 시각까지 수집해 둔 기록만 쓰는 전향 자료 후보로 먼저 분류하고, 과거 날짜가 붙은 게시물을 과거에 이미 볼 수 있었다고 가정하지 않습니다. 대량 수집 API·이용범위·등록농가 대표성은 미확인입니다. 개인명·전화·필지 정밀위치는 이번 목적의 집계에 필요하지 않습니다.

### 4. 직접적인 향후 2·3순 출하계획은 자료 제공 협의 경로

정부 발표에는 산지유통인 출하약정과 출하조절시설이 등장하고, 제주 수급관리센터에는 품목별 수급관리 활동이 확인됩니다. 따라서 **제주 수급관리센터·해당 작목 생산자단체/농협, 배추 주산지 농협·출하조절시설, aT 수급 담당 조직**에 다음 비식별 집계의 보유·제공 여부를 문의하는 경로가 있습니다. 실제 제공을 약속받거나 자료를 확보한 상태는 아닙니다. 이번 작업에서 연락을 보내지 않았습니다.

- 기준시점별 향후 주/순별 계획물량과 출하 예정 지역·시장, 품목/작형/단위.
- 계획 최초 등록·수정·취소 시각과 각 판본, 확정/잠정 구분.
- 실제 출고/도착/경매량을 서로 구분한 사후 대조자료.
- 참여 농가·면적·계약물량의 집계 범위, 등록률, 중복 출하처리 규칙.
- 과거 판본 보존 시작일, 제공 가능 기간·주기·형식·비용·재사용 조건.

특히 현재 시점의 ‘최종 수정된 과거 계획’만 받으면 당시 이용 가능한 정보가 아닙니다. 버전 이력이 없을 경우 전향 스냅숏부터 시작해야 합니다. 2·3순 계획물량이 없고 당일 출고만 있으면 선행 공급자료 확보에 성공했다고 표시하지 않습니다.
