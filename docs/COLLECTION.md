# 데이터 수집·검증 실행 기록

기준일: 2026-09-28 KST. 본 문서는 실제 실행한 코드·조건·자료 범위·검증 한계를 기록한다. [기획안](PLAN.md)의 결정사항을 변경하는 문서가 아니다.

## 저장 구분

- `data/feasibility.sqlite`: 이전 수동 조사 표본. 전체 학습자료가 아니며 본수집이 덮어쓰지 않는다.
- `data/agri.sqlite`: 검토된 Python 수집 코드가 기록할 본수집 DB.
- `docs/data-feasibility-evidence.json`: 이전 조사 요청·원응답 근거. 로컬에 유지하며 Git 제외.
- `runs/`: 본수집 실행 결과와 검증 출력. 로컬에 유지하며 Git 제외.

공식 API 원본과 수집시각을 보존하고 기간 전체 조회 완료 여부를 별도로 관리한다. 휴장·무거래·실패를 구분할 근거가 없으면 자동 채움하지 않는다. 과거 원응답이 현재 수정본일 수 있으므로 미래정보 없는 백테스트를 완료했다고 표기하지 않는다.

## 구현·검토 상태

수집·검증 Python은 `gpt-6-luna`가 작성하고 `gpt-6-astra`가 OCR 파일 선정·규칙 확인 후 검토했다. 차단 결함을 수정하고 재검토한 버전만 실 API에 실행했다. 최종 코드의 오프라인 회귀 검사 25개가 통과했다. 이는 예측성능 검증이 아니다.

현재 승인된 `agri_data/collector.py` SHA-256은 `e3ca950508ad1545cfe73f6441b33241433556eeb1815f69c0742f518793e383`, 테스트는 `fc219a83f751d6b4492c5a98da9c792ed41c4a5564fd734fb22397b1777092ac`다. 코드 커밋은 `a88e987`이다. 최초 생산자료 실행은 `b4b5a66c0028842fc67661d87f0f0672d9e14276281af81fd28bbc7ecea69721`, 완료된 기상 실행은 `20757f31b224dea44ae73fa0f36d1125cd59f0b35e37d1c57309752e04c6eded` 버전이었다. 이후 차이는 ASOS 응답 처리와 수입 요청 묶음에 한정된다.

실행에서 ASOS `numOfRows=1000` 요청은 오류 99를 반환했고, 999로 낮춘 뒤 과거 무자료의 `03 / NO_DATA` 응답을 확인했다. Luna가 정확한 응답 변형만 추가하고 Astra가 재승인했다. 실패 원응답은 DB에 남아 있으며 성공으로 덮어쓰지 않았다.

## 실행 방법과 저장 구조

Python 3.10 이상과 TLS 검증이 가능한 시스템 `curl`을 사용한다. 핵심 수집은 별도 Python 패키지 설치 없이 실행할 수 있다. Parquet 내보내기는 선택 기능이며 `pyarrow`가 별도로 필요하다.

```bash
# 외부 .env는 원격 저장소에 포함하지 않는다. 실제 경로를 인자로 지정한다.
python3 -m agri_data.collector production --env-file /path/to/kosis.env --db data/agri.sqlite --start 1980-01-01 --end 2026-09-27 --max-requests 12 --rate 2
python3 -m agri_data.collector weather --env-file /path/to/portal.env --db data/agri.sqlite --start 1904-01-01 --end 2026-09-27 --station 100 --station 108 --station 261 --max-requests 800 --rate 2
python3 -m agri_data.collector imports --env-file /path/to/portal.env --db data/agri.sqlite --start 1988-01-01 --end 2026-08-31 --max-requests 500 --rate 2
python3 -m agri_data.collector status --db data/agri.sqlite
python3 -m agri_data.collector validate --db data/agri.sqlite --job-id 1
```

가격 명령은 `prices --source origin` 또는 `--source sale`에 기간과 반복 가능한 `--market`을 지정한다. `--crop`을 생략하면 배추·무·양파·마늘·건고추의 중분류 원자료를 모두 수집한다. 마늘 전체를 깐마늘 최종 타깃이라고 해석하지 않는다. 깐마늘 소분류만 조회하려면 `--crop garlic --garlic-subcodes`를 지정한다. 품목 코드의 역사적 유효성은 별도 검증한다.

같은 조건의 미완료 작업을 재실행하면 그 작업 안의 완료 조회를 재사용하고 나머지를 재개한다. 이미 작업 전체가 완료됐으면 새 작업으로 다시 수집하므로 여러 작업의 같은 관측값을 무조건 합산하지 않는다. `--max-requests`는 코드 조회·재시도를 포함한 이번 실행의 실제 HTTP 시도 한도다. 한도 소진은 미완료 상태와 종료코드 2로 남긴다. `--refresh`는 재개하는 작업에서도 완료 조회의 새 응답 버전을 만든다. 수입은 최대 12개월, 기상은 최대 365일 묶음으로 요청하고 페이지 완전성을 확인한다. 수입 정책 표식을 작업 설정에 남겨 이전 월별 작업과 혼합하지 않는다.

DB에는 `jobs`(실행 조건), `planned_queries`(전체 계획/현재 상태), `request_attempts`(실제 HTTP 시도), `source_requests`(원응답·해시·출처·수집시각·버전), `raw_records`, `normalized_records`를 보관한다. 일별 파일은 생성하지 않는다. 정규화 행은 원문 필드를 JSON으로 유지하며 날짜와 품질 표시를 추가한다. 최종 일별 가격 타깃이나 백테스트용 특성 테이블을 만들어 둔 것은 아니다.

연간·월간 자료의 `reference_date`는 편의를 위한 해당 연도/월 첫날이다. 실제 일별 관측일이나 공개일이 아니다. 원문의 `PRD_DE`/`year`와 통계 주기를 함께 읽어야 한다. 모든 신규 응답은 `current_retrieved_vintage`이며, 확인하지 못한 `published_at`과 `version_published_at`은 null로 남긴다.

`validate`는 요청·페이지·행 수·관계 무결성·완료 상태를 검사하며 미완료 작업이 포함되면 실패를 반환한다. 품질 표시는 원자료 해석상의 주의사항으로 별도 출력한다. `quality_flags` 합계는 보관된 모든 응답 버전을 포함하므로 고유 관측 건수와 다를 수 있다. 사용할 버전은 `planned_queries.epoch_id`와 연결해 선택한다. 원천 API가 원자적 스냅샷을 제공하지 않으므로 페이지 조회 중 총건수가 그대로인 내용 변경까지 완전히 검출할 수는 없다.

### 해석과 후속 검증

- 생산 3개 표의 원문 4,802행에는 목표 품목 외 항목도 포함된다. 목표 5작물의 면적/생산량 숫자 값은 460행이다. 배추·무는 1980~2024년, 건고추는 1980~2025년, 양파·마늘은 1980~2026년이다. 마늘 전체 생산량을 깐마늘 생산량으로 바꾸어 부르지 않는다. 전체 표에 있는 158개의 비숫자/결측 표시는 그대로 보존했다.
- 수입은 1988-01~2026-08, 6개 HS 접두부를 234회 조회했다. 161개는 자료가 있고 73개는 정상 0건이었다. 4,619행 중 161행은 `총계`이며 세부행과 함께 합산하지 않는다. 월별 세부 4,458행의 실제 응답 범위는 1995-01~2026-08이다. 1988~1994의 조회 결과가 0건이라는 사실을 당시 무역량 0으로 해석하지 않는다.
- 깐마늘 세부코드 `0703201000`의 이번 최초 응답은 2000-03이다. 더 오래된 `0703200000`은 마늘 전체여서 같은 정의로 연결할 수 없다. 배추·무·깐마늘 등은 최초~최종월 사이에 응답 없는 월도 있으므로 월별 연속 자료 확보를 의미하지 않는다.
- 양파의 구·신 코드가 2022년 상반기에 중첩되며, 건고추도 구 코드 `0904201000`과 새 코드 `0904210000`이 2012-01·02·06에 함께 양수 수입량을 반환했다. 공식 코드 대응·집계 관계를 확인하기 전 무조건 합산/치환하지 않는다. 수입 품질 표시의 `negative:balPayments`는 정상 무역수지 적자를 포함하며 잘못된 음수 수입량이라는 뜻이 아니다.
- 2026-09-23 원천 5,698행과 정산 1,711행을 시장·품목 대/중분류·물량 단위 코드로 묶은 130개 그룹에서 총금액·총물량 합계가 일치했다. 소수 셋째 자리 기준의 보조 SQL 대조이며 개별 거래의 진위나 공식 타깃 가격 산식까지 검증한 것은 아니다. 원천의 낙찰시각 누락 4,443행, 음수 수량/금액 4행, 낙찰가×수량과 총금액 불일치 2행을 보존했다. 정산에도 음수 총물량/금액 1행이 있다.

이 검증은 수집·저장 정합성과 원자료의 사용 제한에 관한 것이다. 예측 모델 성능, 발표 당시 정보만 이용한 백테스트, DM 검정, 아이디어 가설의 성공은 아직 검증하지 않았다.

남은 작업은 가격의 장기 일별 범위를 시장별로 확대하고, 깐마늘/건고추의 희소 거래와 거래방식, 코드 개정, 휴장 근거, 발표 당시 자료 버전을 점검하는 것이다. 국가별 수입·추가 산지 기상·역사적 발표 예보는 이번 배치에 포함하지 않았다. 현 단계 결과로 바로 장기 백테스트를 시작하거나 성능 개선을 주장하지 않는다.

## 본수집 범위와 중단 기준

가격은 2014년부터 확인된 원천자료를 출발점으로 삼아 기간·시장 범위를 확장한다. 이전 연도 표본 0건을 해당 연도 전체 부재라고 판단하지 않는다. 시장 코드 목록과 5품목군을 기준으로 날짜별 조회 계획을 남기고, 실행예산으로 나누어 진행한다. 가락 또는 몇 시장만 수집한 결과를 전국 가격으로 표시하지 않는다.

외부자료는 생산통계의 장기 수록기간, 수입통계의 HS 개정 전후, 기상 지점별 실제 보유기간을 조사·수집한다. 주어진 조회 범위에 대한 요청 완료와 각 날짜/항목의 관측값 존재를 구분한다. 모든 자료에서 최초 공표본 확보 여부를 별도 표시한다.

API 인증 실패·일일 호출 한도·반복적인 서비스 오류·페이지 수 불일치가 발생하면 원인을 보존하고 해당 작업을 미완료로 둔다. 정상 0건은 조회 결과이며 가격 0원·시장 휴장으로 변환하지 않는다. 초기 실행은 호출예산과 디스크 사용량을 확인하면서 확대한다. 조사 당시 가용 디스크는 약 28GiB였으므로 대규모 원천 적재 전에 증가량을 확인한다.

호출량 산정 예: 2014-01-01~2026-09-27은 4,653일이며, 33개 코드×5품목군을 날짜별로 조회하면 첫 페이지에만 767,745회가 필요하다. 이는 시장별 실제 제공기간을 아직 좁히지 않은 탐색 상한이며 추가 페이지·재시도·코드 조회는 별도다. [원천 API 안내](https://www.data.go.kr/data/15141810/openapi.do)는 개발계정 10,000회와 일일 한도 오류를 명시한다. 따라서 단일 배치를 전체 장기 전국자료 수집 완료로 보고할 수 없다. 호출 한도 확대는 같은 API 페이지의 운영계정/트래픽 안내를 확인할 사항이며, 에이전트가 대신 신청하지 않았다. 실제 한도 도달과 자체 실행예산 중단을 결과에서 구분한다.

## 일괄 자료 검토

[aT 농산물 품목별 도매정보](https://www.data.go.kr/data/15134857/fileData.do)의 공식 ZIP도 구조를 확인했다. 약 20MB 압축/109MB 비압축이며 2024-07-08~2026-06-30 이름의 네 CSV를 포함한다. 헤더는 경매일자·시장코드/명·품목코드/명·변경총물량·경매낙찰총금액으로, 원천 API의 소분류·매매구분·원산지·등급을 그대로 재현하기에는 정보가 부족하다. 특히 깐마늘을 마늘 전체와 분리할 근거를 확인하지 못했다. 따라서 현재 API 본수집을 이 파일로 대체하지 않는다. 파일명 범위를 실제 완전한 데이터 기간이라고 확정한 것도 아니다.
