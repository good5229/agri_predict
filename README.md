# 농산물 경락가 예측 프로젝트

배추·무·양파·깐마늘·건고추의 국내 도매시장 경락가를 예측하고, 가격 동향과 예측의 배경을 직관적으로 보여주는 대시보드를 준비한다.

- [합의된 기획안](docs/PLAN.md): 목표, 데이터, 실험, 모델 채택, 대시보드, 단계별 완료 기준.
- [데이터 확보 조사](docs/data-feasibility.md): 공식 출처, 실제 표본 조회, 코드·집계·공개시점의 제약.
- [수집 실행 안내](docs/COLLECTION.md): 검토가 끝난 코드의 실행 방법과 실제 수집 상태.

기획과 데이터 수집·검증에 이어, 실제 학습모델의 순차 평가 결과를 확인하는 대시보드를 구현했다. Ridge 회귀·부스팅 트리와 직전가격 기준모델을 비교하며, 공모전 공식 성능 향상은 아직 입증되지 않았다. 가설검증 성공 후 아이디어 기술서를 작성하며 신청·제출·원격 업로드를 자동으로 수행하지 않는다.

수집기는 `python3 -m agri_data.collector --help`로 실행 방법을 확인한다. 실제 자료는 `data/agri.sqlite`에 보관하며, 기간·배치별 확보 결과와 품질 제한은 위 수집 실행 안내에 기록한다. Python 3.10 이상과 시스템 `curl`이 필요하고, 핵심 수집에는 추가 Python 패키지가 필요하지 않다.

장기 가격자료를 매일 오전 **9시(KST)** 사용자 crontab으로 이어서 수집하도록 등록했다. **2026-09-29 첫 예약 실행은 09:00~09:31에 정상 종료해 2016년 잔여 구간 조회를 완료했다.** 수집 1분 전인 **매일 오전 8시 59분 잠자기 해제**도 macOS 전원 예약에 등록했다. 추가 요청에 따라 하루 한 연도 제한을 제거하고, 가락·강서 두 시장의 가장 이른 미완료 구간부터 **일일 호출 예산이 남는 동안 다음 연도로 계속 진행**하도록 변경했다. 종료일은 2026-09-27이며, 호출 제한이나 오류로 남은 구간은 다음 날 재개한다. 전원이 켜진 상태와 인터넷 연결이 필요하다. 상세 범위·예산·설치 상태는 [일일 수집 안내](docs/COLLECTION.md#매일-오전-9시-장기-가격-수집)를 참고한다. 학습과 동결 평가 결과는 자동으로 갱신하지 않는다.

`python3 -m agri_data.coverage --db data/agri.sqlite`는 중복 수집 버전을 구분해 가격자료의 월별 확보 범위를 읽기 전용 JSON으로 출력한다. 과거 생산통계의 원문·발표시각·단위 근거는 [발표자료 목록](docs/publication-evidence.json)에 별도로 기록한다.

## 저장소와 데이터

코드·기획·실행 설명은 Git으로 추적한다. 인증키, `.env`, `data/`, `runs/`, 대량 원응답 JSON은 추적하지 않는다. 데이터는 삭제되는 것이 아니라 로컬 DB에 별도로 남는다. 원격 저장소는 아직 설정하지 않았다. 나중에 사용자가 정한 원격 URL을 `origin`으로 등록해 업로드할 수 있다.

데이터나 인증키 없이도 수집 조건·실행 방법·검증 코드가 재현 가능하도록 관리한다. 데이터 없는 새 복제본에서 연구 결과를 재현하려면 동일한 원자료 또는 승인된 API 접근이 별도로 필요하다. 데이터의 배포 여부는 이용조건과 공모전 재현 규칙에 따라 결정한다.

## 개발 순서

수집·검증 Python 코드 작성은 **Luna**, 검토는 **Astra**가 담당한다. 인증정보 보호, 누락과 정상 0건 구분, 페이지 완전성, 재개·재시도, 수정본 보존, 날짜/수치 해석을 검토하고 필요한 수정이 끝난 버전만 실 API에 실행한다. 추가 요청에 따라 모델 학습과 대시보드 구현도 진행하며, 학습 Python 역시 같은 작성·검토 순서를 적용한다.

## 성능 대시보드

프로젝트 폴더에서 다음을 실행한 후 [대시보드 열기](http://127.0.0.1:4173)로 접속한다. 대시보드 서버는 Node.js 18 이상을 사용하며 외부 Node 패키지나 API 키가 필요하지 않다. 실행 스크립트는 설치된 Node가 오래된 경우 Codex에 포함된 런타임을 찾는다. 모델 학습에는 아래 Python 의존성을 설치한다.

```bash
# 검토된 코드로 가격자료 생성 (DB 읽기 전용, API 호출 없음)
python3 -m agri_data.dashboard --db data/agri.sqlite --output outputs/prices-dashboard.json

# 최초 1회 학습 환경 준비: Python 3.12 필요 (현재 작업환경은 준비 완료)
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-modeling.txt

# 실제 학습 및 일별 순차 평가. 기존 outputs/dashboard.json은 성공 시 교체
.venv/bin/python -m agri_data.modeling

# 서버 실행, 종료는 Ctrl+C. 다른 포트는 PORT=4174 ./start-dashboard.sh
./start-dashboard.sh
```

- 배추·무·양파·깐마늘·건고추별 실제가격(초록 실선)과 예측가격(황토색 점선), 1~10일 예측거리, 조회기간, 일·주·월·분기 차트 및 일별 결과 CSV를 제공한다. 학습된 모델과 매일·매주·매월·매계절 재학습 주기를 선택한다.
- 현재 연결된 자료는 **가락·강서의 2014~2015년 경매·kg 거래**다. 2014년 이력을 포함해 기준시점까지 마지막 관측가격을 찾고, **2015년의 실제가격이 존재하는 날짜**만 후향적으로 평가한다. 국내 시장의 거래이며 원산지는 제한하지 않는다. 전국 대표가격이나 공모전 공식 타깃으로 확정된 집계가 아니다.
- 가격은 해당 날짜에 포함되는 거래의 **부호 있는 총금액 합 / 부호 있는 총중량 합**이다. 음수 정정 거래를 보존하며, 잘못된 단위·코드·수치 및 비양수 순집계는 제외 사유를 남긴다. 마늘 전체를 깐마늘로 사용하지 않고 확인된 소분류만 포함한다.
- Ridge 회귀와 [히스토그램 부스팅 회귀](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html)를 품목별로 학습한다. 현재는 가격·거래량 이력과 달력 정보로 고정한 첫 실험이며, 전체 후보군 탐색이나 외부자료 추가 실험을 완료한 최종 채택 모델은 아니다. 학습 가능한 날짜가 부족하면 모델을 억지로 만들지 않고 화면에 이유를 표시한다.
- [순차 시계열 검증](https://otexts.com/fpp3/tscv.html) 방식으로 2014년 이력부터 학습하고 2015년 평가기간을 하루씩 진행한다. 예측을 만든 뒤 대상일의 실제가격이 관측되면 오차를 계산한다. 이후 재학습 때에는 그때까지 정답이 알려진 날짜만 추가한다. 평가자료가 나중의 학습에 들어갈 수 있는 **확장 학습창 방식**이며, 2015년 전체를 튜닝한 뒤 같은 구간을 독립 시험이라고 부르지 않는다. 각 예측에 예측 기준일·학습 종료일·참조 관측일을 남긴다.
- 일별·주별(월요일 시작)·월별·계절별(3·6·9·12월 시작) 재학습을 각각 수행한다. 재학습 사이에도 새 가격 이력으로 매일 예측한다. 1~10일 예측의 초기 평가일을 포함하려면 2014년 말 예측이 필요하므로, 첫 학습 종료일도 각 예측 기준일보다 늦지 않게 둔다.
- 기준모델은 학습 없이 예측 기준일까지 관측된 마지막 가격을 유지한다. 모든 모델은 참조 관측이 기준일보다 14일을 초과해 오래되면 예측하지 않는다. 결측 날짜를 휴장으로 간주하거나 실제가격을 임의로 채우지 않는다. 현재 수정본을 사용하므로 당시 공개자료를 재현한 엄격한 실시간 백테스트가 아니다.
- MAE·MAPE·RMSE는 선택한 날짜와 예측거리의 동일 일별 가격쌍으로 계산한다. 주·월·분기 차트는 같은 날짜쌍의 가격을 단순 평균하며 지표는 일별로 유지한다. 예측 없는 집계구간은 실제가격만 보여준다. 건고추 등 표본이 적은 품목은 경고한다.
- ‘하루씩 평가하기’는 저장된 순차 평가 결과를 관측일 순으로 재생하며, 진행일 이후 실제가격과 오차는 숨긴다. 일·주·월·계절별 성능표는 일별 예측오차를 해당 기간으로 묶어 계산한다. 겨울은 12~2월이며 2015년 경계에서 나뉘는 겨울은 실제 포함 날짜를 표시한다. 이 기능은 실시간 API 자동 수집 서비스가 아니다.
- 검증된 가격범위, 중기 2순·3순 예측, 변수 기여도와 DM 검정은 아직 없다. 범위 옵션은 준비 전으로 표시한다. 초기 모델 결과를 공모전 성능 개선의 증거로 해석하지 않는다.

2026-09-28 실행에서는 배추·무·양파에 대해 두 모델 × 네 재학습 주기의 결과가 생성됐다. 2015년 실제 관측일은 각각 306·306·303일이다. 깐마늘·건고추는 같은 경매 조건에서 9·14일뿐이며 초기 훈련자료도 부족해 학습모델을 생성하지 않았다. 두 품목은 관측가격·기준모델과 자료 부족 사유를 표시한다. 매일 재학습·1일 뒤 예측에서 두 학습모델 모두 세 품목의 MAE가 직전가격 기준모델보다 높았으므로, 이번 실행으로 모델 채택이나 성능 향상을 주장하지 않는다. 모델별 다른 예측거리와 시기 성능은 대시보드에서 확인할 수 있다.

### 추가 수집과 단계별 비교

2016년 1분기 추가 수집은 가락·강서의 3월 26일까지 날짜별 조회를 완료했고 이후 HTTP 429가 반복되어 미완료 상태로 보존했다. 추가 원천 거래는 65,928행이며 깐마늘·건고추의 경매 자료 부족은 계속된다. 전체 분기 수집 완료나 전국 자료 확보로 해석하지 않는다. 구체적인 조회·실패 상태는 [수집 기록](docs/COLLECTION.md)에 있다.

추가 실험은 기존 모델을 기준으로 (1) 상대 변화·동일 요일·거래일 변수, (2) 시장·거래구성, (3) 목표값 표현·예측거리별 학습, (4) 발표 근거가 확인된 외부자료를 순서대로 비교한다. 2015년 개발구간에서 구성 선택을 끝낸 후 2016년 1분기를 별도 평가한다. 외부자료는 검증된 당시 발표값만 사용하며 가격 자체는 현재 수정본에 기반한 후향적 실험이다. 새 실험은 기존 대시보드의 2015년 결과를 덮어쓰지 않는다.

실험 코드는 Luna 작성·Astra 검토 후 실행한다. 최초 실행 명령은 다음과 같다. 개발 탐색은 월별 재학습으로 고정하고 매일 1~10일 예측을 발행한다. 별도 평가에서는 일·주·월·계절별 재학습 결과를 모두 보고하되 평가 결과로 선택을 바꾸지 않는다.

```bash
.venv/bin/python -u -m agri_data.experiments --mode development --db data/agri.sqlite --output outputs/experiments-development.json --baseline-dashboard outputs/prices-dashboard.json
.venv/bin/python -u -m agri_data.experiments --mode holdout --db data/agri.sqlite --development-file outputs/experiments-development.json --output outputs/experiments-holdout.json --baseline-dashboard outputs/prices-dashboard.json
```

기존 출력 파일의 덮어쓰기와 동일 개발 결과의 재평가를 차단한다. 이미 실행한 뒤 위 명령을 반복하면 거절된다. 실패한 평가도 claim을 남기며 이를 삭제해 재선택하지 않는다. 날짜별 원가격·거래량 대조, 추출 자료의 canonical hash, 공표본과 선택 구성 동결을 확인하고, 기간·예측거리별 MAE/MAPE/RMSE와 표본 수를 기록한다. 확증용 DM 비교군은 최종 월별 재학습 winner 대 E0의 5품목×10예측거리×2손실함수로 사전 지정하며, 계산 불가능한 비교도 Holm 비교 수에서 임의 제외하지 않는다. 다른 재학습 주기는 탐색적 보고다.

| 무 | 미개선, 기존 변수 유지 | 미개선, 제외 | MAE·MAPE 동시 개선 후보 없음 | 같은 이유로 제외 |
| 양파 | 거래일 변수 채택 | 추가 개선으로 채택 | 원 단위 가격 변화량, 통합 예측거리 모델 | 검증된 생산·면적 발표본을 추가해 실제 비교했으나 악화되어 제외 |
| 깐마늘·건고추 | 학습 관측 부족 | 평가 불가 | 학습모델 생성하지 않음 | 평가 불가 |

단계 채택은 직전 구성 대비 두 지표의 동시 개선 조건이며 운영모델 최종 채택과 구분한다. 개선 후보 간에는 MAPE, 다음 MAE 순서로 선택했다. MAPE는 내부 비교 지표이며 공식 공모전 점수로 확정한 것이 아니다.

아래는 사전 지정한 **월별 재학습, 1~10일 예측 전체**의 별도 평가다. 계획 구간은 2016-01-01~03-31, 실제 평가 관측은 2016-01-04~03-26이며 세 품목 각각 69일×10예측거리=690쌍이다. 690개의 독립 관측일이라는 뜻이 아니다. 각 모델은 이후 재학습 시점까지 관측된 정답을 추가하는 확장 학습창을 사용했다.

| 품목 | 직전가격 MAE / MAPE | 기존 HistGB(E0) MAE / MAPE | 동결 후보 MAE / MAPE | 해석 |
|---|---:|---:|---:|---|
| 배추 | 87.91 / 13.03% | 109.93 / 14.90% | 91.64 / 12.70% | E0 개선, 직전가격 대비 MAE 악화로 전체 성공 아님 |
| 무 | 114.14 / 19.98% | 139.95 / 22.95% | 139.95 / 22.95% | 후보 변경 없음, 직전가격보다 열세 |
| 양파 | 75.15 / 5.60% | 78.74 / 5.78% | 71.66 / 5.27% | 두 기준 대비 평균 지표 개선, 통계적 우월성 미확인 |

MAE 단위는 원/kg이다. 세 품목의 예측 coverage=1은 **확보된 실제가격에 대한 예측 비율**이며, 분기 전체 수집률이나 모든 날짜의 실제 거래 존재를 뜻하지 않는다. 깐마늘은 추가 경매 관측 2일이 있어도 이전 관측과의 간격 때문에 14일 참조가격 제한을 통과한 평가쌍이 없고, 건고추는 추가 경매 관측 자체가 없다. 두 품목을 가격 0이나 장기간 이월값으로 채우지 않았다.

Holm 보정한 100개 사전 비교 중 배추 9일 후 예측만 E0 대비 두 손실에서 유의했다(절대오차 보정 p=0.0142, 절대백분율오차 p=0.0268). 이것은 모든 예측거리나 직전가격 기준선에 대한 우월성 검정이 아니다. 양파는 E0 대비 MAE 8.98%, MAPE 8.75% 개선했고 직전가격 대비 각각 4.64%, 5.73% 개선했지만, 보정 후 유의한 예측거리는 없었다. 따라서 현 결과로 5품목 공모전 검증 성공이나 운영모델 교체를 선언하지 않는다.

일·주·월·계절별 재학습은 모두 실행했고 일·주·월·계절별 오차와 예측거리별 결과를 저장했다. 탐색적으로 배추 후보의 일별 재학습 MAE/MAPE는 87.26/12.26%, 주별은 87.54/12.16%였고, 양파 후보는 일별 79.36/5.83%, 주별 81.35/5.95%로 월별보다 나빴다. 이 평가값을 보고 재학습 주기를 다시 선택하지 않았다.

취약점도 유지한다. 배추 후보의 7일 후 MAPE는 E0보다 소폭 악화됐다. 양파 후보는 1월 MAE가 E0의 55.52에서 61.40으로 악화되고 2·3월에 개선되어 평균 이득을 만들었다. 무는 모든 제안 단계에서 채택 조건을 통과하지 못했고, 별도 평가의 모든 재학습 주기에서 직전가격 기준선보다 열세였다. 이런 시기 차이만으로 계절·기상·수급을 원인으로 단정하지 않는다.

상세 결과는 로컬 [개발 결과](outputs/experiments-development.json), [별도 평가 결과](outputs/experiments-holdout.json)에 있다. 원자료 및 생성 결과는 Git에서 제외한다. 원천 수정본 기반·두 시장·한 분기·분기 말 누락이라는 한계를 유지하며, 후속 확인에는 더 긴 미사용 기간과 깐마늘·건고추의 다른 시장 자료가 필요하다.

가격 내보내기는 `schemaVersion: 1`, 학습 결과는 `schemaVersion: 2`다. 각 품목은 `observations[{date, actual, ...}]`, 기준모델 `predictions[]`, 학습모델 `runs[{modelId, cadence, predictions, fits, ...}]`를 갖는다. 학습 예측에는 `origin`, `target`, `horizon`, `predicted`, `sourceDate`, `fitCutoff`가 필요하다. 원자료 출처·선택 배치·집계 제외 내역과 학습 설정·환경을 함께 보존한다. 학습 결과와 모델 파일은 `outputs/`에서 관리하며 Git에 넣지 않는다.

서버는 `127.0.0.1`에만 열리고 정해진 화면 파일 및 `outputs/dashboard.json`만 제공한다. DB·인증키는 웹으로 노출하지 않는다. 생성 데이터는 Git에서 제외한다. 새 복제본에서는 원자료를 확보하고 화면용 데이터를 다시 생성해야 한다.

검증: `python3 -m unittest discover -s tests -p 'test_dashboard.py'`, `.venv/bin/python -m unittest discover -s tests -p 'test_modeling.py'`와 Node 18 이상의 `node --test dashboard/*.test.mjs`. 로컬 서버 검증에는 루프백 포트 실행이 가능한 환경이 필요하다.
